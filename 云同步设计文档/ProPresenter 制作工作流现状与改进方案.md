# **ProPresenter 制作工作流现状与改进方案**

## **TL;DR**

* **目标**：把"多渠道收集 → 制作 → 审核 → 播放"变成**稳定、可协作、可回滚**的流程，减少周六晚高压与现场风险。
* **现状问题**：信息分散、单机制作、无法并行、发布前变更频繁。
* **路线**：Phase 1 简化同步；Phase 2 版本化协作；Phase 3 自动化/AI 辅助。

---

## **现有工作流（As-Is）**

1. **内容收集**
   * Google Sheet 事工总表：讲员、读经人、证道经文
   * 微信群（屏幕每周更新）：证道主题、小标题
   * 微信群（敬拜群）：诗歌题目、歌词、顺序
   * Google Doc（每周串词）：宣召、认罪悔改、报告事项变动
2. **内容制作**
   * 固定在**播放电脑**上制作（同工需要物理取机、带机到教会）
   * 现场播放也在同一台电脑
3. **发布前阻碍点**
   * 证道标题通常**周六晚**才最终确定 → 大量制作被压到最后一晚

---

## **主要痛点（Pain Points）**

* **信息分散**：多个渠道来回找，口径/更新时间不一致，易漏项/错项
* **单点故障**：只在播放电脑制作，物理交接成本高，容易误覆盖
* **无法并行**：同工不能各自完成部分内容后合并，返工多
* **最后一晚高压**：周六晚集中改动，出错率高、熬夜影响周日质量
* **样式不一致**：跨机字体/主题不统一，换行错位、可读性下降
* **媒体路径混乱**：背景图/视频引用个人路径，换机即"丢素材"
* **缺少回滚**：没有周度打包与版本记录，难以恢复稳定版本
* **临时修订无章**：周日早上改动无流程，风险不可控

---

## **改进路线（To-Be，简化版）**

### **Phase 1｜简化同步（1周）**

* **目标**：让同工在**自己电脑**制作，**通过GitHub同步**到播放机
* **动作**：
* 使用纯Git工作流，删除LFS和Google Drive依赖
* 媒体文件手动管理，.pro文件通过GitHub同步
* **产出**：可在播放机快速拉取的GitHub仓库

### **Phase 2｜版本化协作（2–3周）**

* **目标**：多人并行、可追溯、可回滚
* **动作**：
* 用 GitHub Desktop 管理**文本与清单**（歌词/经文/串词）
* 每周一个分支 → 审核合并；播放机只读拉取
* **产出**：稳定主分支 + 周度归档 + 明确责任与审计记录

### **Phase 3｜自动化/AI（4–6周）**

* **目标**：半自动/自动生成当周内容，降低重复劳动与临时风险
* **动作**：
* 脚本从 Sheet/Doc 汇总生成 Manifest，**自动创建 Playlist/文稿**、套用主题
* 提供"**补题 Patch**"一键修改仅限标题相关页；写前自动导出备份
* **产出**：一键生成/更新 + 日志审计 + 稳定回滚

---

## **简化后的文件管理策略**

### **通过GitHub同步的文件**
- **Libraries/** 中的所有 `.pro` 文件（演示文稿）
- **Playlists/** 中的所有播放列表文件
- **Themes/** 中的主题文件
- **Configuration/** 中的配置文件
- 所有脚本和文档文件

### **需要手动管理的文件**
- **Media/** 中的所有媒体文件（视频、音频、图片）
- **background music/** 中的音频文件
- **logo/** 中的图片文件
- **Doc Sync/** 中的文档文件

### **优势**
- ✅ 简单易学，新同工容易掌握
- ✅ 无需额外软件（LFS、Google Drive）
- ✅ 标准Git操作，兼容性好
- ✅ 版本控制完整，可回滚
- ⚠️ 媒体文件需要手动管理

---

## **建议时间线与里程碑**

* **W1**：Phase 1 落地 + 固化走查清单
* **W2–W3**：Phase 2 上线（文本清单进 Git；分支/合并流程跑通）
* **W4–W6**：Phase 3 PoC（Manifest 校验 + 一键生成/补题 Patch）

## **新同工培训要点**

### **基础操作（30分钟）**
1. **克隆仓库**：`git clone <url>`
2. **拉取更新**：`git pull origin main`
3. **查看状态**：`git status`
4. **提交更改**：`git add . && git commit -m "描述"`
5. **推送更改**：`git push origin main`

### **媒体文件管理**
1. **手动复制**：从其他电脑或云存储复制媒体文件
2. **保持结构**：确保文件夹结构一致
3. **定期备份**：使用云存储备份媒体文件

### **协作流程**
1. **制作前**：`git pull` 获取最新版本
2. **制作中**：定期 `git commit` 保存进度
3. **制作后**：`git push` 上传到GitHub
4. **冲突处理**：使用 `git status` 检查冲突

## **风险评估与缓解**

### **风险1：媒体文件丢失**
- **缓解**：建立媒体文件备份流程，使用云存储

### **风险2：Git操作复杂**
- **缓解**：提供详细培训文档，使用GitHub Desktop简化操作

### **风险3：文件冲突**
- **缓解**：建立协作规范，避免同时编辑同一文件

### **风险4：网络问题**
- **缓解**：本地备份重要文件，离线工作能力
