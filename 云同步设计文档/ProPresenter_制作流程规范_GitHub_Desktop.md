# ProPresenter 制作流程规范 (GitHub Desktop 版)

## 📋 概述

本文档规范基于 GitHub Desktop 的 ProPresenter 制作与播放流程，确保每周主日内容制作高效、协作顺畅、播放稳定。

---

## 🛠️ 前期准备

### 软件安装
1. **GitHub Desktop**: [下载安装](https://desktop.github.com/)
2. **ProPresenter 7/8**: 确保已安装并配置
3. **登录 GitHub 账号**并配置仓库访问权限

### 初始设置
1. **克隆仓库**:
   - 打开 GitHub Desktop
   - File → Clone Repository → 选择 ProPresenter 项目
   - 选择本地存储位置
   
2. **配置 ProPresenter**:
   - 设置 ProPresenter 支持文件夹指向克隆的本地目录
   - 验证能够访问 Libraries、Playlists、Themes 等文件夹

## 👥 角色分工

### 制作端 (Content Creator)
- 负责内容编辑和播放列表制作
- 管理 `事项` 和 `敬拜歌曲` 两大库
- 导出轻量级播放列表文件

### 播放端 (Playback Operator)  
- 负责现场播放准备和执行
- 创建当日专用库并导入播放列表
- 现场播放和应急处理

### 协调人 (Coordinator)
- 统筹时间节点和版本管理
- 最终版本确认和质量把关
- 团队沟通协调

## 📅 每周制作流程

### 阶段 1: 制作准备 (周二-周三)

#### 步骤 1: 同步最新内容
1. 打开 GitHub Desktop
2. 点击 **"Fetch origin"** (获取远程更新)
3. 确保在 `main` 分支
4. 如有更新，点击 **"Pull origin"** (下载到本地)

#### 步骤 2: 创建制作分支
1. 点击 **"Current branch"** 按钮
2. 选择 **"New branch"**
3. 分支命名: `YYYY-MM-DD-制作` 
   - 示例: `2025-08-24-制作`
4. 点击 **"Create branch"**

### 阶段 2: 内容制作 (周三-周五)

#### 步骤 3: 编辑内容
1. 打开 ProPresenter
2. 更新 **事项** 库:
   - 宣召、读经、证道、报告等项目
   - 根据当周需要调整内容
3. 更新 **敬拜歌曲** 库:
   - 添加或编辑当周诗歌
   - 检查歌词和背景

#### 步骤 4: 创建播放列表
1. 在 ProPresenter 中创建新的 Playlist
2. 命名: `YYYY-MM-DD_主日崇拜`
   - 示例: `2025-08-24_主日崇拜`
3. 按敬拜顺序添加项目:
   - 从 `事项` 库中选择相应项目
   - 从 `敬拜歌曲` 库中选择当周诗歌
   - 确保顺序正确

### 阶段 3: 导出和提交 (周六)

#### 步骤 5: 导出播放列表
1. 右键点击播放列表
2. 选择 **"Export Playlist..."**
3. **重要**: 取消选择 **"Include Media"** (不包含媒体文件)
4. 保存为: `YYYY-MM-DD_主日崇拜.proPlaylist`
5. 保存到项目根目录

#### 步骤 6: 提交更改
1. 回到 GitHub Desktop
2. 左侧显示所有修改的文件
3. 检查文件列表确认无误
4. 在左下角 **Summary** 框输入:
   ```
   完成 YYYY-MM-DD 主日内容制作
   
   - 更新事项库和敬拜歌曲库
   - 创建主日播放列表
   - 导出轻量级播放列表文件
   ```
5. 点击 **"Commit to YYYY-MM-DD-制作"**
6. 点击 **"Push origin"** (上传到云端)

## 🎭 播放准备流程

### 阶段 4: 播放端准备 (主日上午)

#### 步骤 7: 获取最新制作内容
1. 打开 GitHub Desktop
2. 点击 **"Current branch"** → 选择制作分支
   - 示例: `2025-08-24-制作`
3. 点击 **"Fetch origin"** 检查更新
4. 如有更新，点击 **"Pull origin"**

#### 步骤 8: 创建播放库
1. 打开 ProPresenter
2. 新建 Library:
   - 命名: `YYYY-MM-DD_主日`
   - 示例: `2025-08-24_主日`
3. 导入播放列表:
   - 找到 `YYYY-MM-DD_主日崇拜.proPlaylist` 文件
   - 拖拽到新建库中或右键导入

### 阶段 5: 现场检查 (播放前 ≥10分钟)

#### 步骤 9: 播放前验证
- [ ] **内容完整性**: 逐项检查播放列表顺序
- [ ] **文字内容**: 确认经文、歌词、公告无误
- [ ] **背景素材**: 检查图片、视频是否正常显示
- [ ] **转场效果**: 测试关键转场是否流畅
- [ ] **音频测试**: 如有背景音乐确认音量合适
- [ ] **应急预案**: 确认备用素材和默认背景可用

## 📐 命名规范

### 分支命名规范
- **主分支**: `main`
- **制作分支**: `YYYY-MM-DD-制作`
- **播放分支**: `YYYY-MM-DD-播放` (现场修改时使用)

### 文件命名规范
- **播放列表导出**: `YYYY-MM-DD_主日崇拜.proPlaylist`
- **播放库**: `YYYY-MM-DD_主日`
- **特殊场合**: `YYYY-MM-DD_特别聚会名称`

### 提交消息规范
- **制作完成**: `完成 YYYY-MM-DD 主日内容制作`
- **内容修改**: `修改 YYYY-MM-DD [具体修改内容]`
- **紧急修正**: `紧急修正 YYYY-MM-DD [问题描述]`

## ⚡ GitHub Desktop 操作速查

### 常用按钮功能
| 按钮 | 功能 | 使用时机 |
|------|------|----------|
| **Fetch origin** | 检查远程更新 | 开始工作前 |
| **Pull origin** | 下载最新内容 | 有更新时 |
| **Push origin** | 上传本地更改 | 完成提交后 |
| **Current branch** | 切换/创建分支 | 开始新任务 |
| **Commit** | 保存当前修改 | 完成阶段性工作 |

### 分支操作
1. **创建新分支**: Current branch → New branch
2. **切换分支**: Current branch → 选择目标分支
3. **合并分支**: (通常由协调人在 GitHub 网站操作)

## 🕐 时间节点管理

### 标准时间线
- **周二**: 开始制作，创建制作分支
- **周三-周五**: 内容制作和调整
- **周六 20:00**: 最终版本提交，内容冻结
- **主日上午**: 播放端准备和现场检查

### 冻结政策
- **周六 20:00 后**: 不再接受内容修改
- **紧急情况**: 需协调人审批
- **现场调整**: 仅限技术问题修正

## 🚨 应急处理

### GitHub Desktop 常见问题

#### 问题 1: 无法推送 (Push failed)
**解决方案:**
1. 点击 **"Fetch origin"** 检查更新
2. 如有冲突，选择 **"Merge"** 或联系协调人
3. 重新推送

#### 问题 2: 找不到播放列表文件
**解决方案:**
1. 确认在正确分支 (制作分支)
2. 确认已执行 **"Pull origin"**
3. 检查文件是否在项目根目录

#### 问题 3: 分支混乱
**解决方案:**
1. 截图当前状态
2. 联系协调人协助
3. 必要时重新克隆仓库

### ProPresenter 问题

#### 问题 1: 播放列表导入失败
**解决方案:**
1. 确认 `.proPlaylist` 文件完整
2. 重新下载播放列表文件
3. 手动创建播放列表作为备用

#### 问题 2: 缺少背景或媒体
**解决方案:**
1. 使用默认背景素材
2. 从 `Media/Assets/` 文件夹选择替代素材
3. 联系制作端确认原始素材

## 🎯 最佳实践

### 团队协作
1. **及时沟通**: 重大修改前通知相关人员
2. **版本控制**: 严格按照分支策略操作
3. **备份意识**: 重要节点及时推送到远程
4. **文档更新**: 流程改进及时更新规范

### 技术建议
1. **定期同步**: 每次工作前先 Fetch + Pull
2. **小步提交**: 阶段性工作完成即提交
3. **清晰命名**: 分支、文件、提交信息都要清晰
4. **测试验证**: 导出后务必测试播放列表

### 风险防控
1. **双重备份**: 重要内容本地和云端双备份
2. **版本回溯**: 保留历史版本以便紧急恢复
3. **权限管理**: 合理设置仓库访问权限
4. **培训更新**: 定期培训确保操作规范
